# 网络管理、故障排查与规划设计

## SNMP

- Manager/NMS 发起管理请求并接收通知，Agent 暴露受管对象，MIB 描述对象层次和标识。
- 常见 UDP 端口：Agent 请求/响应 161，Trap/Inform 通知 162。
- SNMPv1/v2c 以 community 为主要访问控制，安全性弱；SNMPv3 支持认证和加密等安全能力。
- Poll 是管理站周期查询；Trap 是代理主动通知且通常不确认；Inform 带确认机制，可靠性更高但开销更大。

管理对象题常考 OID 树。读取一个标量对象时，实例通常以 `.0` 结尾；表对象按索引定位具体行。

## 分层故障排查

统一模板：

```text
现象 -> 影响范围 -> 最近变更 -> 分层证据 -> 根因 -> 最小修复 -> 验证
```

建议从影响面和最便宜的证据开始，不机械限定只能从物理层向上：

| 层面 | 关键检查 | 常见证据 |
|---|---|---|
| 物理 | 电源、模块、线缆、光功率、速率/双工 | 接口 Up/Down、误码、丢包 |
| 二层 | VLAN、Trunk、STP、MAC、聚合 | VLAN 表、MAC 表、STP 角色 |
| 三层 | IP/掩码、ARP/ND、路由、ACL/NAT | 邻居表、路由表、ACL 命中 |
| 传输 | TCP/UDP 端口、会话状态 | `ss`、连接表、抓包 |
| 应用 | DNS、证书、服务进程、配置与权限 | 查询结果、日志、HTTP 状态 |

验证修复不能只写“ping 通”：根据原业务选择 DNS 查询、端口连接、路由邻接、ACL 命中计数或应用事务。

## 高频故障模式

- 单主机不通：先查本机地址、掩码、网关、VLAN 和接入端口。
- 同 VLAN 可通、跨 VLAN 不通：查三层网关、路由、ACL 和回程路径。
- 单向通信：优先查 ACL 方向、策略路由、NAT 状态和非对称路由。
- 域名不通但 IP 可通：查 DNS，而不是继续更换物理链路。
- 间歇性丢包：查链路错误、环路、拥塞、聚合不一致、无线干扰和设备资源。
- OSPF 无邻居：查网段/掩码、Area、Hello/Dead、认证、网络类型、接口状态。

## 网络规划步骤

1. 需求：用户/终端数、应用、流量、位置、合规、预算、增长。
2. 现状：地址、链路、设备、故障、利用率和运维能力。
3. 逻辑设计：分层、VLAN/VRF、地址、路由、安全域和服务。
4. 物理设计：设备规格、接口、介质、机房、供电和布线。
5. 可靠性：链路/设备/电源冗余、收敛、容量与故障域。
6. 实施：迁移窗口、回退方案、配置模板和变更控制。
7. 验收：功能、性能、安全、故障切换和文档。

## 分层设计

- 接入层连接终端并实施端口安全、VLAN 等边缘策略。
- 汇聚层汇总接入、执行三层边界和策略、缩小故障域。
- 核心层强调高速、稳定和简化，不应堆积过多复杂策略。

小型网络可合并核心与汇聚。题目问设备选型时结合端口数量、吞吐、背板、转发率、PoE、上联、冗余和协议能力，而不是只看标称带宽。

## 地址与容量规划

- VLSM 从最大需求子网开始分配，并预留增长空间。
- 汇总边界应与拓扑和路由策略一致；仅为了得到短前缀而把不连续地址强行汇总会产生黑洞风险。
- 设备/链路容量不仅看平均流量，还要看峰值、突发、协议开销、冗余失效后的剩余容量和未来增长。

## 可靠性

独立串联系统全部正常才成功：

```text
Rseries = R1 × R2 × ... × Rn
```

两个独立并联系统至少一个正常：

```text
Rparallel = 1 - (1 - R1)(1 - R2)
```

题目若存在公共电源、同一机房或共同链路，故障并不独立，不能机械套并联公式。

## 应用技术题得分结构

- 先写结论关键词，再补必要原因。
- 设备/介质选择要把需求与指标一一对应。
- 安全设计至少说明控制对象、部署位置和效果。
- 故障题必须给证据和验证步骤；只写“重启设备”通常得分有限。
