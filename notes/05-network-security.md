# 网络安全

## 密码学最小框架

| 能力 | 常用机制 | 不能单独保证什么 |
|---|---|---|
| 机密性 | 对称/非对称加密 | 不自动证明发送者身份 |
| 完整性 | 哈希、MAC、数字签名 | 普通哈希不能阻止攻击者同时替换报文和摘要 |
| 身份认证 | 口令、证书、挑战应答、多因素 | 不等于授权 |
| 不可否认 | 合理管理下的数字签名 | 不等于内容加密 |
| 可用性 | 冗余、限流、备份、抗攻击 | 不是密码算法直接提供 |

- 对称密码速度快，适合大量数据；密钥分发是主要问题。
- 非对称密码使用密钥对，常用于密钥交换、签名和身份认证，性能通常低于对称密码。
- 数字签名：发送方用自己的私钥对摘要相关数据签名，接收方用发送方公钥验证。验签本身不提供机密性。
- MAC/HMAC 使用双方共享秘密验证完整性和来源，不提供第三方不可否认性。

## PKI 与证书

- CA 签发并管理证书，把主体身份与公钥绑定。
- RA 可承担注册审核等职责，具体体系依部署而定。
- 验证证书要检查信任链、有效期、用途/名称和撤销状态；“能打开证书”不等于可信。
- CRL 是撤销列表；OCSP 用于在线查询证书状态。

## 常见认证协议

- PAP 通常以明文或可还原形式发送凭据，安全性弱。
- CHAP 使用挑战—响应，避免直接在线路上传送口令；双方共享秘密仍需安全管理。
- Kerberos 以票据和对称密码为核心，依赖可信 KDC 和较准确的时间同步。

## ACL、防火墙与入侵检测

- ACL 自上而下逐条匹配，命中即停止；末尾通常存在隐式拒绝。配置前先安排规则顺序。
- 标准/基本 ACL 主要看源地址，扩展/高级 ACL 可看源、目的、协议和端口。
- 包过滤关注报文头字段；状态检测防火墙还跟踪连接状态；应用代理可理解更高层语义但开销更大。
- IDS 侧重检测和告警，IPS 通常部署在流量路径中并可阻断。二者都不能替代补丁、最小权限和备份。

## IPsec

- AH 提供完整性、来源认证和防重放，不提供机密性；NAT 场景兼容性较差。
- ESP 可提供机密性，也可结合认证/完整性保护，是更常见选择。
- 传输模式主要保护上层负载，保留原 IP 首部；隧道模式封装整个原始 IP 数据报，并增加新的外层 IP 首部。
- SA 常用三元组识别：SPI、目的地址、安全协议；通信通常需要分别建立单向 SA。
- IKE 用于协商安全参数和密钥，数据保护由 IPsec SA 承担。

## 常见攻击与最小防护

| 现象/攻击 | 识别 | 最小防护方向 |
|---|---|---|
| ARP 欺骗 | IP-MAC 映射被伪造 | DHCP Snooping/DAI、静态绑定、分段 |
| DHCP 欺骗 | 非授权服务器发放配置 | DHCP Snooping、接入口信任边界 |
| MAC 泛洪 | 交换表被大量伪造源 MAC 填满 | 端口安全、限速、监控 |
| SYN Flood | 大量半连接消耗资源 | SYN Cookie、限速、清洗、扩容 |
| DNS 污染/劫持 | 返回错误解析结果 | DNSSEC 验证、可信解析、传输保护 |
| SQL 注入 | 输入进入 SQL 语义 | 参数化查询、最小数据库权限 |
| XSS | 恶意脚本在浏览器执行 | 输出编码、CSP、输入约束 |
| 木马 | 伪装为正常程序并建立控制 | 白名单、EDR、最小权限、网络隔离 |
| 蠕虫 | 自动扫描和传播 | 补丁、分段、入口/出口控制 |

## 安全题答题顺序

1. 明确资产、威胁和信任边界。
2. 说明攻击利用的条件，而不只报攻击名称。
3. 给出预防、检测、响应至少两个层次的控制。
4. 指出部署位置和验证证据，例如日志、告警、规则命中或连通性变化。
